# routecheck v0.2: AS-path sets reaching AS-ANY (on rpsl v0.30.0) — design

Approved by the user 2026-10-18 (scope, `Verdict.AnySets`, re-downloading the real data).

## Why

routecheck v0.1 requires rpsl v0.29.0, whose peval fails a whole policy when an AS-path regexp names an
as-set reaching AS-ANY (`*resolve.AnySetError`). Rulings R19/R21 turned that into an "unevaluable"
report: every route Undecided. On RIPE that was one report, AS8308's import from AS1887 (39 routes in the
0.1.0 real-data run), whose regexp names `AS1887:AS-Peerings:AS8501` (`members: AS-ANY`).

rpsl v0.30.0 evaluates it: in an AS-path regexp such a set is a `resolve.ASNSet` whose `Any()` is true —
`Has` is true for every AS, while `List()` is empty and `Len()` is 0. In filter position (`accept AS-X`,
`NOT AS-X`) and from `ExpandAS`/`ExpandPrefixes`/`EvalFilter` it is still `*AnySetError`.

## Decisions

1. **Dependencies.** Require `rpsl`, `rpsl/types`, `rpsl/resolve` v0.30.0 (ast and lexer indirect, the
   same). `scripts/check.sh`'s pin check moves with go.mod. rpsl's `resolve/testdata/snapshot` did not
   change between v0.29.0 and v0.30.0, so `testdata/irr/snapshot` only gets its README's version line.
2. **pathre** needs no code change: it asks `Has`, true for every AS. Its doc says so.
3. **The test oracle (`internal/reoracle`)** checks `Any()` before `Len()`: an any-set is any AS. Its
   generator gains an any-set (`AS-ALL`, in `Sets()`), so pathre is held to the oracle on it.
4. **Vectors.** rpsl's routemodel vectors are format version 2, with `any_sets` (names that are any-sets).
   `pathre/testdata/routemodel-vectors.jsonl` is regenerated from rpsl's main at v0.30.0; the reader
   reads `any_sets` and refuses a header whose `version` is not 2 (a version-1 reader would read an
   any-set as absent: matches nothing).
5. **`Verdict.AnySets []string`.** For an Accepted verdict: the canonical names, sorted and
   deduplicated, of the sets reaching AS-ANY that the AS-path tests (either polarity) of the conjunct
   that accepted the route name; nil otherwise, and nil for Rejected and Undecided. Strings, not
   `types.SetName`, so the JSON is the names. Text output: `accepted by clause N (AS-X reaches AS-ANY:
   any AS)`, `(AS-X, AS-Y reach AS-ANY: any AS)` for several, before any "after undecided" part. JSON:
   the field as Go encodes it (the view keeps Verdict's field names).
6. **R19/R21 stay** for what still errors: AS-ANY or RS-ANY in filter position. Their tests move from
   `<^AS64500 AS-ANYSET$>` to `accept AS-ANYSET`; a new test pins the regexp position (evaluated,
   Accepted, `AnySets` names the set). Every text saying an AS-path set gives "unevaluable", or that
   AS-ANY waits for rpsl's peval, is corrected (check.go, verdict docs, CLAUDE.md R19 and Known
   limitations, docs/routecheck.md, SECURITY.md).
7. **Real data** (re-downloaded 2026-10-18: RIPE splits, rrc00 bview 2026-10-18 08:00, route-views2 RIB
   2026-10-18 12:00, NTT VRPs). The run reports how many accepted routes carry `AnySets` and how many
   reports are unevaluable; the CHANGELOG gives the new figures. The data is newer than 0.1.0's, so
   figures are not compared one to one.
8. **Release** as routecheck v0.2.0, after the user's go-ahead for each outward step.

## Non-goals

No new meaning for AS-ANY in filter position; no change to pathre's matching; no new Reason kind
(Reasons is why a route is Undecided, plus peval's notes on Accepted).
